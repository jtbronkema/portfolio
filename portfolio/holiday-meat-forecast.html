Problem Statement

Each year, Fresh Thyme Market needs to forecast how much of each holiday meat item every store will sell at Thanksgiving, Christmas, and Easter. That forecast was produced through a legacy system managed by category managers. I partnered with the Meat merchandising team to build a machine learning forecast to replace it across all 70 Fresh Thyme Market stores.

Our Approach

The project had two parts: a new demand forecast to set how much product each store should receive, and a daily inventory tool to help the meat team manage that product once it arrived.

The Forecasting Model

I built XGBoost machine learning models to forecast demand for holiday meat items for Thanksgiving, Christmas, and Easter at every Fresh Thyme Market store. Working closely with the Meat merchandising team, we put the new forecast into use in place of the legacy forecasting process previously run by category managers.

One model per store, per SKU
30+ holiday meat SKUs × 70 stores = 2,100+ XGBoost models

Rather than one model for the whole chain, I trained a separate model for every product at every store, so each model learned the demand pattern of that exact item at that exact location.

Scaling to 2,100+ Models

Training thousands of models one at a time would have been slow, so I built and ran the program on a remote desktop and used Python’s joblib package to parallelize it. Each product-store pair became its own task, and joblib spread those tasks across all of the machine’s CPU cores so many models trained at the same time, making the program run far more efficiently. The simplified example below shows the approach:

holiday_forecast.py
import pandas as pd
from joblib import Parallel, delayed
from xgboost import XGBRegressor

# Daily holiday meat sales: one row per product, store, and day
sales = pd.read_csv("holiday_meat_sales.csv", parse_dates=["date"])

FEATURES = ["days_to_holiday", "day_of_week", "price", "on_promo",
            "prior_year_units", "store_traffic"]
TARGET = "units_sold"
FORECAST_YEAR = 2024


def train_and_forecast(product, store, df):
    """Train one XGBoost model for a single product at a single store."""
    train = df[df["holiday_year"] < FORECAST_YEAR]
    upcoming = df[df["holiday_year"] == FORECAST_YEAR]

    model = XGBRegressor(
        n_estimators=300,
        max_depth=4,
        learning_rate=0.05,
        subsample=0.8,
        objective="reg:squarederror",
    )
    model.fit(train[FEATURES], train[TARGET])
    forecast = upcoming.assign(
        forecast_units=model.predict(upcoming[FEATURES])
    )
    return (product, store), model, forecast


# One task per product-store pair: 30+ SKUs x 70 stores = 2,100+ models
tasks = []
for product in sales["product_id"].unique():
    product_df = sales[sales["product_id"] == product]

    for store in product_df["store_id"].unique():
        df = product_df[product_df["store_id"] == store].sort_values("date")
        tasks.append(delayed(train_and_forecast)(product, store, df))

# Train every model in parallel across all CPU cores on the remote desktop
results = Parallel(n_jobs=-1, verbose=5)(tasks)

models = {key: model for key, model, _ in results}
forecast_df = pd.concat([forecast for _, _, forecast in results])

Daily Inventory Visibility Tool

Alongside the forecast, I built a tool that gave the meat team a daily view of every holiday product at every store:

  1. How many units of each product were in the store
  2. How many units had sold
  3. How many more units were scheduled to be delivered in the coming days

With this view, category managers could see which stores were running long or short on a product and move product between stores before it went to waste.
